# Repository orientation

## Purpose

Establish source of truth, boundaries, validation routes and the smallest useful
context capsule before implementation or review.

## When to use

Use when entering a repository, resuming a campaign, or when scope or ownership
is unclear.

## When not to use

Skip for a known one-file edit with an already verified target and validation route.

## Inputs

Repository instructions, `.engineering/PROFILE.md` when present, task objective,
version-control state, manifests, maps and test/build metadata.

## Process

Read project instructions, profile, status and metadata; create a structural map;
locate entry points, contracts, persistence, integrations and tests; use text
search only to close gaps; return facts, unknowns, risks and next reads.

## Evidence

Record paths, symbols, commands, ownership boundaries and reproducible outputs.

## Done criteria

Source of truth, affected area, validation route, baseline, risks and next reads
are identified.

## Stop / escalation conditions

Stop on conflicting authority, inaccessible evidence or ambiguous destructive scope.
